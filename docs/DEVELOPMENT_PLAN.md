# TIP输入法项目 AI Agent 开发全计划

> 适配 Windows 平台 | 基于 TSF 现代输入法框架 | AI Agent 全流程辅助开发 | 代码托管至 GitHub

---

## 一、项目总览

### 1.1 项目目标

开发一款轻量、开源、高性能的 Windows 桌面拼音输入法，基于微软官方 **TSF（Text Services Framework）** 现代框架实现，支持基础拼音输入、自定义短语、万级本地词库，兼顾输入流畅度与系统兼容性，全流程由 AI Agent 辅助完成编码、调试、文档与测试工作。

### 1.2 代码仓库

- **仓库地址：** `https://github.com/SpadyDong/tip-ime`
- **开源协议：** MIT 协议（宽松商用友好，无传染限制）
- **提交规范：** 采用 Git 语义化提交，分模块迭代合入主干

### 1.3 适配平台

- **系统支持：** Windows 10 1903+ / Windows 11 全版本
- **架构支持：** x86（32 位）、x64（64 位）双架构编译
- **兼容场景：** 桌面软件、UWP 应用、全屏游戏、高 DPI 多屏、远程桌面

### 1.4 核心能力（V1.0 版本）

- 全拼音输入、简拼支持、基础模糊音适配
- 本地词库支持 10000+ 词条，输入检索延迟 < 50ms
- 跟随光标候选栏、数字选词、翻页、基础皮肤
- 中英文切换、全半角切换、中英文标点切换
- 独立设置面板、自定义短语导入导出
- 标准安装包，支持一键注册 / 卸载输入法

## 二、整体架构设计

### 2.1 三层架构总览

采用「系统适配层 + 业务逻辑层 + UI 表现层」分层架构，层间通过接口解耦，便于 AI Agent 分模块并行开发。

```text
┌─────────────────────────────────────────────────┐
│              UI 表现层 (Win32/Direct2D)         │
│  候选栏窗口 | 设置面板 | 状态栏图标 | 软键盘    │
├─────────────────────────────────────────────────┤
│              业务逻辑层 (纯C++无系统依赖)       │
│  拼音引擎 | 词库管理 | 配置管理 | 输入状态机    │
├─────────────────────────────────────────────────┤
│              TSF 系统适配层 (COM组件)           │
│  键盘事件拦截 | 文本提交 | 上下文管理 | COM注册 │
└─────────────────────────────────────────────────┘
```

### 2.2 各层详细设计

#### 2.2.1 TSF 系统适配层（内核层）

输入法与 Windows 系统交互的核心，以 COM DLL 形式运行，对接系统 `ctfmon.exe` 调度。

**核心接口实现：**

- `ITfTextInputProcessor`：输入法服务入口
- `ITfKeyEventSink`：键盘事件拦截与处理
- `ITfContextOwnerCompositionSink`：输入组合串管理
- `ITfThreadMgrEventSink`：线程上下文生命周期管理

**核心职责：**

- 接收系统键盘消息
- 上报候选文本
- 提交最终文字
- 同步输入光标坐标

#### 2.2.2 输入业务逻辑层

输入法核心算法与业务逻辑，与系统 API 解耦，可单独测试与移植。

- **拼音解析引擎：** 拼音切分、简拼匹配、多音字处理、模糊音映射
- **词库检索引擎：** Trie 前缀树索引 + 哈希快速匹配，支持万级词条低延迟检索
- **词库管理模块：** 基础词库加载、用户自定义词增删、词频动态更新
- **配置管理模块：** 读写配置文件、快捷键映射、输入偏好设置
- **输入状态机：** 中英文状态、全半角、标点模式切换

#### 2.2.3 UI 交互表现层

负责所有可视化交互，采用 Win32 原生窗口 + Direct2D 渲染，保证全场景兼容。

- **候选栏窗口：** 跟随输入光标、悬浮置顶、无焦点抢占、多列候选布局
- **状态栏图标：** 托盘图标、输入状态指示、快捷切换入口
- **设置面板：** 独立 Win32 窗口程序，提供可视化配置界面
- **皮肤渲染：** 支持基础配色自定义、高 DPI 自适应

### 2.3 核心数据流

1. 系统键盘消息 → TSF 层拦截 → 转发至业务层拼音引擎
2. 拼音引擎匹配词库 → 生成候选词列表 → 回传 UI 层渲染候选栏
3. 用户选词 / 上屏 → TSF 层提交文本至系统输入框
4. 用户配置修改 → 配置层持久化 → 实时更新输入行为

## 四、分阶段开发流程与开发计划

单人 + AI Agent 协作模式，总周期约 **18 天** 完成 V1.0 可用版本。

### 阶段 0：环境搭建与仓库初始化（1 天）

**目标：** 完成开发环境、仓库骨架、基础依赖准备。

- GitHub 仓库初始化，提交 `LICENSE`、`README`、基础目录结构
- 本地开发环境搭建：Visual Studio 2022、Windows SDK、Git
- AI Agent 生成项目编译配置：`CMakeLists.txt` / VS 工程文件
- 提交初始骨架代码，完成 CI 基础配置

**AI Agent 分工：**

- **代码生成 Agent：** 生成目录骨架、编译配置、基础工具类
- **文档 Agent：** 编写初始 README、开发环境搭建文档

### 阶段 1：TSF 最小内核原型（3 天）

**目标：** 实现可注册、可输入汉字的最小 TSF 输入法 DLL。

- 实现 COM 组件基础框架：类工厂、DLL 入口、注册注销逻辑
- 实现核心 TSF 接口：键盘拦截、组合串管理、文本上屏
- 极简候选逻辑：固定拼音映射，验证输入链路通断
- 完成 DLL 编译、系统注册、记事本输入验证

**交付物：** 可正常输入单个汉字的 TSF 输入法 DLL

**AI Agent 分工：**

- **代码生成 Agent：** 生成全套 TSF 接口样板代码、COM 注册逻辑
- **调试 Agent：** 协助定位注册失败、输入无响应等系统级报错

### 阶段 2：拼音输入引擎与词库系统（5 天）

**目标：** 完成完整拼音输入能力，支持万级词库流畅检索。

**AI Agent 分工：**

## 五、AI Agent 分工与协作开发计划

### 5.1 Agent 角色划分

设置 4 类专项 Agent，各司其职，并行提升开发效率。

| Agent 角色 | 核心职责 | 输出产物 |
|------------|----------|----------|
| 代码生成 Agent | 按模块生成 C++ 源码、接口实现、工具类、编译脚本 | 可编译的功能代码、头文件、工程配置 |
| 调试排错 Agent | 分析编译报错、运行时崩溃、系统兼容问题，给出修复方案 | 问题根因分析、修复代码片段、排查步骤 |
| 测试验证 Agent | 生成单元测试用例、性能测试脚本、兼容性测试清单 | 测试代码、测试报告、验收标准 |
| 文档运维 Agent | 编写开发文档、README、使用说明、仓库维护、CI 配置 | 技术文档、发布说明、自动化脚本 |

### 5.2 Agent 协作流程

1. **需求拆解：** 将阶段目标拆分为单个模块任务
2. **代码生成：** 代码生成 Agent 输出初始代码，人工确认架构合理性
3. **编译调试：** 人工编译，报错信息输入调试 Agent，迭代修复至编译通过
4. **测试验证：** 测试 Agent 生成用例，验证功能正确性与性能指标
5. **文档同步：** 文档 Agent 同步更新对应模块开发文档
6. **代码提交：** 通过评审后合入仓库对应分支

### 5.3 AI 辅助开发核心落地点

- **TSF 样板代码生成：** 替代人工查阅晦涩的微软文档，快速生成 COM 接口框架，减少 70% 底层样板代码工作量
- **报错快速定位：** 系统级 COM 报错、注册失败、输入无响应等问题，AI 基于知识库快速给出排查路径
- **算法代码生成：** Trie 树、拼音切分、词库序列化等标准化算法，AI 一键生成可运行代码
- **测试用例自动生成：** 针对拼音引擎、词库检索自动生成边界测试用例，覆盖人工遗漏场景
- **文档自动同步：** 代码迭代后自动更新对应文档，减少人工维护成本

## 七、开发注意事项（Windows 输入法专项踩坑指南）

### 7.1 TSF COM 开发核心注意事项

- **调试方式受限：** TSF DLL 运行在系统 `ctfmon.exe` 和各应用进程内，无法直接断点调试，必须通过日志定位问题，项目初期务必完善日志系统
- **COM 注册权限：** 注册输入法需要管理员权限写入注册表，安装包必须申请管理员权限
- **线程模型：** TSF 必须使用 STA 单线程单元模型，跨线程操作必须通过列集，否则会出现随机崩溃
- **引用计数管理：** COM 接口引用计数错误会导致内存泄漏、进程无法退出，AI 生成代码需人工核对 AddRef/Release 配对
- **上下文生命周期：** 切换输入框时输入上下文会重建，必须正确处理销毁事件，避免悬空指针崩溃

### 7.2 词库性能注意事项

- 禁止使用线性遍历匹配词条，1 万词条必须用 Trie 前缀树或哈希索引，保证 O(1)~O(n) 检索复杂度
- 词库检索必须放到异步子线程执行，禁止阻塞 TSF 主线程，防止应用界面卡死
- 词库文件采用二进制序列化存储，避免启动时逐行解析文本，大幅提升加载速度
- 高频词与低频词分层存储，优先匹配高频词，进一步降低检索耗时

### 7.3 系统兼容注意事项

- **高 DPI 适配：** 候选窗口必须启用 Per-Monitor DPI 感知，通过系统 API 获取光标坐标，禁止硬编码像素位置
- **UWP 沙箱兼容：** UWP 应用权限隔离，无法使用部分窗口消息，必须通过 TSF 标准接口获取光标位置
- **全屏游戏兼容：** 全屏独占模式下普通窗口无法置顶，需采用分层窗口 + 置顶属性，必要时做游戏场景降级
- **32/64 位双编译：** 系统存在 32 位程序时，必须同时部署 32 位输入法 DLL，否则 32 位软件无法调用输入法

### 7.4 部署与安全注意事项

- **数字签名：** 正式发布版本建议加代码签名证书，避免被 Windows Defender 拦截为恶意软件
- **卸载清理：** 卸载时必须完整清理注册表项、DLL 文件、用户数据，避免残留导致系统输入法异常
- **权限最小化：** 输入法运行时无需管理员权限，仅安装注册时需要，避免高权限带来的安全风险
- **异常保护：** 核心逻辑增加 SEH 异常捕获，避免输入法崩溃导致宿主应用一起崩溃

### 7.5 开源合规注意事项

- 第三方依赖严格遵循开源协议，避免引入 GPL 强传染组件
- 引用开源代码需保留原版权声明，放入对应目录的 license 文件
- 词库资源采用开源词库（如雾凇拼音词库），确保无版权风险
- 项目整体采用 MIT 协议，允许商用修改与分发

## 八、仓库管理与交付规范

### 8.1 分支管理

- `main`：主干分支，存放稳定可发布版本
- `dev`：开发分支，日常迭代合入
- `feature/xxx`：功能分支，单个功能开发完成后合入 dev
- `release/vx.x.x`：发布分支，用于版本发布与修复
- `hotfix/xxx`：紧急问题修复分支

### 8.2 提交规范

采用语义化提交信息，格式：`类型(模块): 提交描述`

**类型：**

- `feat`（新功能）
- `fix`（修复）
- `docs`（文档）
- `refactor`（重构）
- `test`（测试）
- `chore`（工程配置）

**示例：** `feat(dictionary): 新增 Trie 树词库检索实现`

### 8.3 版本发布流程

1. 从 `dev` 切出 `release` 分支
2. 执行全量测试与回归，修复发布前问题
3. 更新版本号、更新日志、发布说明
4. 合入 `main` 分支，打 tag 标签
5. 编译打包安装包，上传至 GitHub Release
